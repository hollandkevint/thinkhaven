## Fix list (below CONFIRMED, ordered by strategy impact)

1. **Claim 7, MISSING: the close gate.** This is the sentence ThinkHaven's approach paragraph ends on, and the first key metric ("Completed pressure tests: sessions that finish with a decision artifact," `STRATEGY.md:24`). Today `status: 'completed'` is reachable with no artifact, so the metric can count sessions the strategy would call failures. Candidate shape: `completePhase` refuses (or flags) final-phase completion unless a `decision_record`/`lean_canvas` output or a `recommend_action` row exists for the session, plus a test that completes a bare session and asserts the refusal.
2. **Claims 1–2, WEAK: board routing has no discriminating coverage.** The adversarial stance is the differentiator vs. "one flattering voice," and its entire mechanism (`resolveSpeakerKey`, the `switchSpeaker` handler, `currentSpeaker` attribution in the agentic loop) can silently break. Matches the known-context note in the audit packet: only a sprint posthog source-grep touches it. Candidate tests: `resolveSpeakerKey` fallback-to-Mary, `switch_speaker` schema-by-name (enum + required `handoff_reason`), and a mocked agentic-loop run asserting post-switch text is attributed to the new speaker.
3. **Claim 5, WEAK: challenge loop is prompt-only and explore-only.** Decide whether ELICIT→CHALLENGE→SYNTHESIZE→DEEP_EXPLORATION should apply beyond the `explore` pathway (the strategy language doesn't scope it), then add unit tests pinning the phase-to-instruction mapping at exchange counts 0/1/2/3+ so a refactor can't silently drop a phase. Side observation for whoever picks this up: code has board offers at exchanges 3/8/15 (`mary-persona.ts:544`) while project memory records 5/12/20; the code is ground truth, the memory note has drifted.
4. **Claim 3, WEAK: anti-sycophancy rests on prompt text.** Lowest urgency because claim 4 gives it one real tested mechanism, but the "commitment" itself has no behavioral check. Cheapest hardening: an eval-style test that feeds an overconfident transcript through `updateSubPersonaState` end-to-end and asserts the resulting prompt contains the devil's-advocate mode section, tying prompt output to detected state rather than to a static string.
